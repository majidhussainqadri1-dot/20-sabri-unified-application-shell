Responsive canonical application shell and integration layer for the Sabri Social Homeopathy Platform.

== Description ==

File 20 owns the global structural shell and continuity layer; native-domain data and authorization remain with canonical companion files.

Future Shell v5 contains exactly eighteen approved enhancements: Command Palette, PWA, offline/weak-network mode, Data Saver, Recent & Resume, module circuit breaker, last-known-good recovery, performance guardian, smart navigation pins, keyboard accessibility, Focus Mode, native-owner Split Workspace, foldable/tablet/ultra-wide adaptation, progressive View Transitions, bounded safe prefetch, language/direction quick control, accessibility preference center and five-state release rings.

Version 1.4.1 completed the first ten-round corrective hardening pass. Version 1.4.2 completed a second independent pass. Version 1.4.3 reconciled later File 00/01/02 contracts and privacy/PWA ownership. Version 1.4.4 reconciled newer File 00/01/02/19/21/24 contracts without transferring native-domain ownership.

Version 1.4.5 completes the fifth independent ten-round review. It corrects the residual Internal release-ring contract and the production-package/evidence pipeline. The final five-state release-ring evaluator remains fail closed. Internal defaults to `manage_options` and can consume an explicit authenticated internal-principal approval through `sabri_shell_future_internal_principal_allowed`; File 20 does not own identity/entitlement truth. REST release-ring configuration remains manager-only.

The 1.4.5 deterministic package excludes repository `tests/` and declared development-only material. CI rejects ZIP path traversal, absolute/wrong-root paths and duplicate entries before extraction, then proves clean production source/stage/extracted file-set and SHA-256 parity. Embedded `MANIFEST.sha256` must equal the external source manifest.

Hostinger staging testing and Founder acceptance remain required before production deployment.

== Installation ==

1. Back up files and database and prove restore.
2. Install or upgrade the exact 1.4.5 candidate on staging only and flush rewrite rules.
3. Verify the package has one canonical root, no `tests/`, and matching embedded/external source manifests.
4. Run Sabri Shell System Check.
5. Verify File 00 identity/authorization/advanced-trust, File 01 foundation registry, File 02 authentication/passkeys, File 19 one-bell, File 21 Home/News five slots, File 24 security-state integration, File 25 visual and File 26 search contracts.
6. Verify `/.well-known/webauthn` is File-02-owned public JSON/no-cache, with Minimal/no visual shell and no private-route misclassification.
7. Test all five release rings, including explicit Internal-principal allow and default-deny cases; REST configuration must remain `manage_options` only.
8. Test root/subdirectory PWA install/update/disable/self-removal/offline, privacy exclusions and protected-path overflow fail-closed behavior.
9. Test keyboard/dialog accessibility, Recent/Resume, Split Workspace provider gating, circuit/LKG recovery, all four layout modes, RTL/LTR, zoom and reduced motion.
10. Complete Hostinger staging, backup/restore/rollback rehearsal and Founder acceptance before production.
