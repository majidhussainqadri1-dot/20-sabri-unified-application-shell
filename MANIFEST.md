## Production-package constitution

For the 1.4.5 candidate, the deterministic package workflow:

1. derives a clean production source set from `sabri-unified-application-shell/`;
2. excludes development-only directories including `tests/`, `node_modules`, `.git`, `.github`, coverage/cache folders and temporary/log files;
3. writes an embedded `MANIFEST.sha256` from that clean production source set;
4. builds exactly one canonical top-level plugin folder;
5. rejects absolute paths, `..` traversal paths, duplicate ZIP names or entries outside the canonical root before extraction;
6. verifies the clean production source, staged package tree and extracted ZIP have the same file set and SHA-256 hashes;
7. requires the embedded manifest to equal the external source manifest;
8. verifies deterministic ZIP SHA-256 and ZIP CRC integrity.

Development tests remain in the repository and run in CI, but they must not ship inside the installable WordPress ZIP.
